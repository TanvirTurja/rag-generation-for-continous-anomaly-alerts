# Clinician Evaluation Kit — Alert-Triggered RAG Explanations (fix/v2 W7)

This package contains everything needed to run the human clinical evaluation of the
generated alert explanations. It is designed to be executed by the author with
3+ qualified raters (e.g., one cardiologist, two monitoring nurses or physicians
with ambulatory-monitoring experience). No software is required by raters beyond a
spreadsheet editor.

## Contents

| File | Purpose |
|---|---|
| `INSTRUCTIONS_for_raters.md` | Plain-language instructions to give each rater |
| `scoring_rubric.md` | Anchored 1–3 / 1–5 definitions for each axis |
| `select_sample.py` | Builds the stratified 60-item sample from v2 outputs (run after W6) |
| `sample_60.csv` | Generated by the script above; the items raters see |
| `scoring_form.csv` | Blank response sheet (one row per item per rater) |
| `analyze_ratings.py` | Computes per-axis means, Fleiss' κ, harm-flag counts from filled forms |

## Procedure

1. Run `python clinician_eval/select_sample.py` (requires `outputs_v2/generation_v2.jsonl`
   from the v2 pipeline).
2. Send each rater: `INSTRUCTIONS_for_raters.md`, `scoring_rubric.md`, `sample_60.csv`,
   and an individual copy of `scoring_form.csv` (named `ratings_<rater_id>.csv`).
3. Raters work independently, untimed (typical: 45–75 minutes). No discussion until
   all forms are returned.
4. Place all filled `ratings_*.csv` in this folder and run
   `python clinician_eval/analyze_ratings.py` → writes `clinician_results.json`.
5. Report the results in the manuscript §Human Evaluation; adjudicate disagreements
   (items where raters differ by ≥2 on any axis) in a consensus meeting, recording
   both pre- and post-adjudication statistics.

## Stratification of the 60 items

- 20 explanations for **labeled true events** (WESAD stress, MIT-BIH arrhythmic
  windows, PTB-XL pathology records — mixed classes)
- 20 **in-the-wild PPG-DaLiA flags** (includes artifact-style conclusions)
- 10 **word-cap ablation** items (300-word explanations)
- 10 **random remaining** items (borderline diversity)

Raters are NOT told which group an item belongs to (the `group` column stays in a
separate key file, `sample_key.csv`, for the analysis only).
